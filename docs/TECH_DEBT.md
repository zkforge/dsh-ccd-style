# 待办与已知边界

## 已知差异（首版有意保留）

- 侧栏顶部没有参考图的 Home/Code 分段控件与 Routines/Customize/More 导航行：DSH 没有对应能力，按约束不制作空按钮；DSH 自己的品牌行与「插件」全局面板行保留，因此侧栏条目与参考图并不一一对应。
- 聊天页顶部的视图切换器（对话／轨迹）已按参考图的分段控件重画，并按用户要求并入顶栏的预设芯片之后；参考图顶栏本身没有这组切换，因此它仍是一处「参考图没有、但原生功能必须可达」的元素。
- 顶栏重排依赖 `.ST7X_W_titleRow`／`.ST7X_W_titleCluster` 用 `display: contents` 溶解后再用 flex `order` 排序。宿主若改动顶栏层级、给这两层加背景或边框，或把切换器移出 `conversation.session.header`，这套排序就会失效——失效时顶栏仍可用（只是切换器回到原位），不会留下半截样式。溶解还会连带丢掉写在这两层上的内边距：宿主的「让开 macOS 红绿灯」留白已手工搬到 `.ST7X_W_crumbs` 上，宿主若把它挪到别处（例如改挂到 header 自己），需要跟着重新核对收起侧栏与全屏两种状态。
- 聊天页的会话用量与上下文占用不再单独占一行，但读数被压缩成「图标 + 一个数字」（`210 tok/s`／`117M tok`／`19%`）：其余事实（轮次、步数、缓存命中率）只在点击后的原生详情面板里可见。选择保留原生面板而不是自绘，是因为数据全部来自宿主。
- 账号菜单页眉只有账号名，参考图还有第二行工作区文案（账号名 · 工作区名）；DSH 的账号行与账号菜单都没有这个字段，插件不编造。
- 统计读数的截取规则依赖宿主当前的标签格式（按 `·` 分段，取含 `/` 的速率段，否则取首段）。宿主换语言或换格式时规则可能失配，此时回退为整句显示，不会显示错误数字。
- 参考图使用 Anthropic Sans／Serif，未获授权分发；插件使用系统字体栈，字形与字宽存在差异。
- 参考图的 Overview 统计卡片与热力图没有实现，详见下一条。

## 未实现

- **statistics**：DSH `0.2.0-rc.2` 没有跨会话的全局用量接口。会话级用量只在当前会话的 `conversation.composer.dock` 中，聚合全局数字需要新增 Host 路由。首版保持关闭，不放示例数据。
- **tool-calls**：保留原生展示与展开；一行概要、展开重构、子调用分组等高级呈现后置。续做时用 `tool.call.toolview`。
- **深色模式**：设计变量与语义 token 覆盖只按浅色校准。
- Windows／Linux 支持、其他 DSH 版本适配。
- 小程序式「更多」聚合入口：目前原生功能仍分散在各自的原生位置。

## 工程待办

- 冷启动后的**渲染层**没有用 CDP 复验（手动重启的实例不带调试端口）。服务端启动图已确认，如需逐项复验，用 `scripts/desktop-coldstart.mjs <report-dir>` 重启并自动采集。
- pnpm 对同一个 `file:` tarball 路径会报 `Already up to date` 而不重新解包，更新已安装插件时必须先 `plugin remove` 再 `add`，或用新文件名重新打包。
- 宿主类名带构建哈希，集中在 `src/client/compat/host-dom.ts`。升级 DSH 版本时必须重新核对；建议在 `probeHost()` 中增加更多锚点断言，让版本漂移尽早暴露。
- `compat/composer-menus.ts` 会在宿主每帧写入后重新定位菜单（宿主 `Menu` 的视口兜底会盖住锚点）。这是唯一一处与宿主抢写内联样式的地方：宿主升级后若改变定位算法，需要重新核对；放得下的菜单完全不干预。
- `compat/stats-values.ts`、`compat/account-menu.ts` 与 `compat/view-switch.ts` 都依赖 MutationObserver 在宿主渲染后补一次标记／属性；跨模块 HMR 重叠时的观察器释放需在真实更新场景中再验证一次。
- `compat/view-switch.ts` 在每次 DOM 变更后量一次选中段（全文档 `childList`/`characterData`/`class`/`aria-selected` 观察）。量测本身很轻（一次选择器 + 两次 `getBoundingClientRect`），但流式输出期间变更频繁；若后续出现可测量的开销，改成只观察顶栏子树即可。
- 分段控件的滑块位置靠 180ms 过渡动画表现「平滑移动」。被遮挡或后台窗口会被 Chromium 节流动画帧，此时滑块会晚一点到位（值仍然正确）；已按 `prefers-reduced-motion` 关闭动画。
- 用 `link:` 方式安装到 profile 时，pnpm 会重新解析被链接项目的依赖；本轮曾在 `link:` → `file:` 切换时导致被链接仓库的 `node_modules` 被清理（源码与 `lib/` 未受影响）。推荐用安装包（`file:`）路径安装，或在链接安装后重新执行 `npm ci`。
- 用户明确停用插件后，插件不会自动重新启用；本项目的启用开关来自 DSH 自动生成的插件设置表单，没有额外的自定义设置行。

解决后移除对应条目，并同步架构、实施状态和验证记录。
