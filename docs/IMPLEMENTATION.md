# 项目状态与实施交接

更新日期：2026-10-02。四个核心界面模块已经实现并在真实 Desktop 中验证；本文件记录每个模块**现在**做了什么、边界在哪，以及剩余动作。结构事实见 [ARCHITECTURE.md](../ARCHITECTURE.md)，需求与截图基准见 [PLAN.md](../PLAN.md)，验证结果见 [验证记录](VERIFICATION.md)。

## 实现方式（统一前提）

新会话页与聊天页都是 `conversation.content` 的两种 phase（`hero` / `active`），Composer 是官方 `conversation.composer.bar`。因此四个模块都**不替换**宿主组件，只做两件事：

1. 通过 `environment.dom.mountStyles()` 挂载作用域样式（`html[data-dsh-ccd-style="true"]`）；
2. 只在必须读取宿主动态几何时使用兼容层（打开中的账号菜单、贴着窗口底边的菜单翻转）。

所有特效样式表都是惰性的：宿主元素尚未渲染时挂载不会产生任何效果，因此可以无条件挂载，避免「在插件面板页启用后切回会话却没有样式」的问题。

## shell

入口：`src/client/features/shell/index.ts` + `shell.css`。

- 去掉 macOS 侧栏的蓝紫渐变底色，改为平铺设计色；
- 分隔线画在侧栏自己的右边缘（1px `--ccd-border`），中列不再重复画左边缘；
- 三列轨道完全交给 `ui-layout`：插件不写宽度、不发布差值，所以拖动分隔条时线与指针同步（实测 ±40px 跟随，收缩到 DSH 自己的 264px 下限）。

## sidebar

入口：`src/client/features/sidebar/index.ts` + `sidebar.css`。

- 侧栏内边距、行高、圆角、选中态按参考图压缩；
- 品牌行压缩为紧凑一行（顶部控制条之下），并与下方导航行同缩进（8px），标志与名称和新会话／插件图标对齐；
- 「新会话」从凸起按钮改为扁平导航行；全局面板行同规格；
- 三行导航共用一条图标列：「新会话」的加号（宿主画 14px）与全局面板图标（16px）统一放进 16px 槽位、同用 8px 间距，实测图标中心都是 26、标签都从 x=42 开始（修复前标签分别从 39／42／42 开始，加号也比另外两个图标偏左）；
- 项目分组与会话行使用宿主类名压缩到 30/28px，时间戳与图标降噪；
- 底部账号行压到 30px（宿主默认 44px）、圆角 8px，并与窗口底边留 8px（`--ccd-sidebar-bottom-padding`），hover 背景不再贴住窗口边缘；分隔线保留在行上方；
- 账号菜单按参考图展开成卡片：236px 宽、账号名作为页眉、28px 行高、末组上方一条细分隔线；菜单条目仍是 DSH 自己的三条（设置／意见反馈／退出登录），插件不增删条目；参考图的 272×208 是六条目 + 双行页眉的尺寸，DSH 只有三条且账号行没有工作区文案，因此取更窄的行高节奏而不是照抄外框；
- 「新会话」「插件」「自动化任务」三行共用 `--ccd-nav-gap`（2px）节奏，hover 背景等距；
- 压缩后的几何只作用于**展开**的侧栏：所有覆盖宿主布局的规则都带 `:not(._3WPZCG_collapsed)`。DSH 收起后是另一套布局（36px 图标轨，图标各自居中在 36×36 按钮里），插件此前的 8px 内缩（品牌行 `padding`、工作区区块头 `padding-left`）与顶栏控制条的 88px 让位会跟着生效，把「添加工作区」「品牌」两个图标推出轨道中线，并让收起动画里的收起按钮先飞到 x=88 再消失；现在收起态一律用宿主自己的数值（实测六个图标中心都在 28，与关闭插件时逐项相同）；
- macOS 展开态 `SidebarRoot` 与收起态 `shell.leading` 的原生按钮共用窗口坐标：非全屏 `88/11`、全屏 `12/11`，28×28；展开态按钮用 `position: fixed` 脱离侧栏裁剪，不随列宽动画移动。框架切到收起态即隐藏侧栏内旧按钮，避免交接期间叠加；非 macOS 仍用原生品牌行／图标轨布局。见验证记录的「侧栏按钮固定到窗口控制区」轮，取代此前仅对齐交接位置的结论。

未做：参考图的 Home/Code 分段控件、Routines/Customize/More 导航行没有对应的 DSH 能力，按约束不制作空按钮；DSH 的品牌行与「插件」面板行保留在原位。

## new-session

入口：`src/client/features/new-session/index.ts` + `new-session.css`。

- 问候块用绝对定位放到页面正中：宿主把问候、工作区行与输入条渲染成同一块（`composerSeat`），这一块被 `margin-top: auto` 推到底部，问候块单独提到内容列的水平／垂直中心（实测 1374×871 下问候块中心 827/456，与 `[data-conversation-content]` 的中心重合）；只调品牌标志大小、标题字级与「预览版」徽章，标题仍由宿主居中；
- 工作区／模式选择行与输入面板对齐：行内边距 = 侧向留白，芯片左边框与输入面板左边框落在同一条竖线上（1374×871 实测两者都是 x=438.5；参考图芯片 982 vs 输入面板 980，相差 1px）；此前比输入面板多出的 4px 会让芯片读成第二列，已去掉；
- 该行两个菜单控件（工作区选择器、Agent 预设芯片）按参考图加上边框：1px `--ccd-border`、8px 圆角、`--ccd-shadow-card` 淡阴影、默认透明底（参考图芯片填充与页面同色，只有边框），hover／展开用 `--ccd-hover`；两者统一为 26px 高；
- 两个芯片的菜单都从窗口底边弹出：宿主 `Menu` 的视口兜底原本会把卡片顶到窗口顶部、盖住 Composer，现由 `compat/composer-menus.ts` 翻到芯片上方（详见 [DSH 兼容说明](DSH_COMPATIBILITY.md)）；
- Composer 区块用 `margin-top: auto` 推到底部；
- 未选择工作区时把宿主 `cardWorkspaceTrigger::after` 的整卡虚线移到当前输入面板；选好工作区后恢复实线，控制行留在框外；点击输入区选择工作区、键盘入口和禁用状态继续由宿主处理；
- `--dsh-chat-content-width` 与 `--dsh-composer-card-max-width` 设为 770px，输入卡片据此居中；
- 参考图 `docs/reference/ccd-new-session.png` 实测（窗口原点 x=112/y=76 @2x）：输入框 y=795..836、x=431..1187（770×41）；实现实测 y=792..833、x=431..1201，误差 ≤3px；
- 控制行在输入框下方 4px，行内元素中心与参考图一致（参考图 y≈851.8，实现 852）。

## conversation

入口：`src/client/features/conversation/index.ts` + `conversation.css`，共用几何在 `src/client/theme/composer.css`。

- 卡片外壳透明化，边框与圆角移到输入面板（`.yhfFVG_scroll`），控制行留在面板下方 4px 处——参考图同样是「有边框的输入面板 + 面板外的控制行」；
- 粘贴／选取的图片预览轨（`ui-attachment` 插件渲染的 `conversation.input.attachments` 插槽，`.dVdiKa_rail`，类钉在 `compat/host-dom.ts`）是面板的兄弟节点；卡片透明后它会悬在页面上面，并把绝对定位到卡片右上角的发送按钮一起带出面板（用户报告的 bug）。有预览轨时两盒并回同一个表面：预览轨画顶盖（无边框底边、上圆角、白底），面板去掉自己的顶盖（无边框顶边、下圆角），卡片零间距让两侧 1px 边框贴合不露缝；图片缩略图的裁剪圆角与输入面板共用 `--ccd-composer-radius`（10px），预览轨无需再为按钮预留格子；
- 新建页默认提示语与正常聊天统一为宿主的「发消息或创建任务, / 调用指令, @ 文件或对话」（英文同样用对应宿主正常聊天文案），由 `compat/composer-placeholder.ts` 同步可见文本和 aria-label，仅适配已知 hero 默认文案，选择工作区及阻断提示不受影响；两页提示语统一单行省略，宽度约束在输入区内并预留发送按钮空间；实际编辑器保留正常换行与多行增长；
- 输入面板最小高度 42px，随内容增长；控制行 28px；输入框底边到窗口底边合计 38px（参考图 34.5px）；
- 发送／停止按钮固定在输入面板底部右侧（24px、透明底、8px 圆角），以控制行的顶边定位，距输入面板底边 9px；多行内容与附件向上扩展时按钮不会上移，控制行换行时也保持与输入面板底边的间距。输入文本预留 30px；DSH 在生成中继续输入时会同时展示停止／发送，两者留 6px 间距，文本预留增至 60px；
- 发送／停止复用 DSH 静态共享库 `ui-primitives` 的 `IconSendOutlineRegular`（细线向上箭头）／`IconStopFillRegular`（1px 小圆角方块）几何，以 16px CSS mask 绘制；官方 SVG 仅隐藏，按钮状态、标签、焦点与发送／停止回调仍由宿主拥有。MIT 版权说明写入包内 `LICENSE`；
- 「+」命令按钮去掉宿主的圆形底色，改为 28px 无底色图标；
- 三个读数与同排控件同形：高度 28px、圆角 8px（等于宿主的 `--dsw-radius-sm`），与模型／权限选择器、`+` 按钮完全一致；选择「和模型／权限选择器统一」而不是保留宿主胶囊形，是因为同一排里的可点控件应当属于同一族；
- 会话用量与上下文占用（`conversation.composer.dock` + `ContextMeter`）不再单独占一行：dock 是卡片的兄弟节点，因此绝对定位到控制行上、**模型选择之前**（偏移量由 `--ccd-trailing-width` 实时测得，见 `compat/stats-values.ts`）；按用户最新要求在宽列显示三个图标及对应简短读数（速率／token 用量／上下文百分比）；实际 Composer 容器 ≤700px 时前两项只留图标、上下文保留百分比。速率／token 数字从原生标签镜像到 `--ccd-stat-value`，不修改宿主文字。点击仍打开原有详情面板；
- 窄列仍保持单行：按实际 Composer 容器宽度（不是窗口宽度）模型按钮按控制行扣除前导按钮、统计簇及间距后的实际剩余宽度限宽，推理等级始终保留，模型名按需省略；在 ≤560px 时权限只留图标并压缩统计按钮内边距；统计偏移始终量完整原生 trailing 组（包括其空插槽产生的间距），框架轨道的 style 与原生模型收缩属性变化会同步更新，属性写入只在数值改变时进行；
- 正文列宽 770px；用户消息气泡底色、圆角、内边距按参考图调整；
- 工具行、推理行、代码块的文字颜色降噪；
- 顶栏合成一行：`.ST7X_W_titleRow` 与 `.ST7X_W_titleCluster` 用 `display: contents` 溶解（不搬动任何宿主节点），再靠 flex `order` 把 DSH 自己的视图切换器排到会话标题之后、Agent 预设芯片与工具图标之前（标题 → 切换器 → 芯片 → 工具图标 → 右角）；宿主为第二行预留的 `min-height: 76px` 随之去掉，会话页顶栏由 76px 收到 49px，空白会话仍保持原来的 40px；
- 溶解掉的那一行原本还承担「让开 macOS 窗口按钮」的留白（`padding-inline-start: max(0px, --dsh-frame-leading-clearance - 20px)`），这条留白改挂在该行的第一个子元素 `.ST7X_W_crumbs` 上：收起侧栏时 `--dsh-frame-leading-clearance` 会跳到 160px（全屏 84px），左栏收起时会话标题省略，仅保留这段窗口控件让位；让位按 `--dsh-frame-leading-clearance - 12px` 计算，不随右栏宽度变化；
- 视图切换器（对话／轨迹）改成参考图的分段控件：宿主自己的 `role="tablist"` 与两个 `role="tab"` 按钮原样使用——角色、标签、点击处理、`aria-selected` 与「开发者工具关闭时隐藏轨迹」的过滤都还是宿主的，插件只画外壳：轨道固定 80×22、每格 40×22、8px 圆角浅灰底（不随列宽缩放），选中段是轨道 `::before` 的白色滑块（1px 边框 + 8px 圆角 + 细分阴影，与参考图同为「滑块铺满选中格」）；滑块位置由 `compat/view-switch.ts` 实测选中按钮后发布 `--ccd-view-x`／`--ccd-view-w`，切换时 180ms 平滑移动，框架 style 改动触发拖动几何刷新，同一选中按钮随布局变化时即时校正（0ms），自触发通知不取消选择动画；`prefers-reduced-motion` 下不动画；
- 顶栏按实际会话列宽精简：移除聊天顶栏不可点击的模式展示，智能体团队保留完整图标与文字；各宽度使用同一套左侧 12px 留白；标题右内边距 8px 加轨道前 2px、轨道后到团队入口 10px，使两处可见间距均为 10px；团队按钮保持完整文字，视图按钮尺寸与字体不变。标题保持自然宽度且上限 112px，不参与列宽收缩，保留所有原生操作按钮与 macOS 窗口控制区让位，顶栏仍为 49px 单行；
- 切换器紧随会话标题（标题文本到轨道可见间距 10px），其后才是 Agent 预设芯片；标题、切换器、芯片靠左成组，工具图标与右角保持贴右。把弹性间距从轨道移到芯片容器上，是因为后续还要在芯片之后加更多同类条目（后台任务等），谁在最后谁就贴右，不需要再动轨道；尾侧「打开应用」主按钮的横向内边距为 3px，「更多操作」宽度为 24px，图标尺寸不变，为最窄列保留可读间距；

未做：参考图顶栏没有这组视图切换（CCD 只有标题 + 芯片 + 图标），本轮按用户要求把它并入顶栏而不是删除；DSH 的 `对话／轨迹` 原生功能因此完全保留。

## statistics

入口：`src/client/features/statistics/index.ts`，状态 `planned`，默认关闭。参考图的 Overview 卡片需要全局会话数、消息数、token 总量、活跃天、峰值时段与热力图。DSH `0.2.0-rc.2` 没有可聚合这些数字的全局用量接口：会话级用量只存在于当前会话的 `conversation.composer.dock`（`ui-chat` StatsPills），跨会话统计需要新增 Host 路由。因此首版不放统计区，也不使用示例数字。续做时先确定 Host 数据边界，再扩展 Host 层。

## 交付与验证工具

`scripts/` 下有三个**不随包发布**的验证工具，用于真实 Desktop 校准：

- `desktop-probe.mjs`：通过渲染进程的 CDP 端点执行表达式、截图、抓取 DOM 结构与控制台；
- `desktop-responsive.mjs`：在一次连接内按多组窗口尺寸渲染、量测并截图；
- `desktop-preview.mjs`：把源码样式表临时注入真实渲染进程，用于插件尚未安装时的视觉校准，`clear` 或刷新即撤销；
- `web-harness.mjs` / `dom-outline.mjs`：在工作区内的沙箱 DSH profile 上做快速迭代。

新增功能后请更新本文件与 [验证记录](VERIFICATION.md)。待处理事项见 [TECH_DEBT.md](TECH_DEBT.md)。
